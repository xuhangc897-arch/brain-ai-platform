# 手机端排版审计与修改计划

审计日期：2026-08-08  
范围：学生端登录、首页、资格审查、实验一、实验二、诊断入口；视口 360×800 与 390×844。后台管理页未纳入本轮。

## 总体结论

首页、登录页和资格审查主体已经具备可用的手机端单列布局。主要缺陷集中在四个实验页共享的固定头部、横向步骤导航、右下角记忆侦探助手，以及实验二的宽表格。前两项持续占用或压缩内容空间，助手会直接遮挡输入区和“上一步 / 下一步”按钮。

## 走查步骤

1. 首页（良好）：360px 下标题、主按钮和背景构图完整；顶部“教师端 / 退出”和轮播箭头约 30–43px，触控尺寸偏小。证据：`accepted/01-home-360.png`。
2. 登录（良好）：360px 下表单完整单列，主要提交按钮清楚；显示密码按钮为 34×34px，游客入口高约 42px，略低于建议触控尺寸。证据：`accepted/02-login-360.png`。
3. 资格审查（基本良好）：390px 下表单与答题区正确单列；粘性头部堆叠为两行模式切换加两个全宽按钮，模式按钮高 28px、操作按钮高 34px，滚动时占空间且触控目标偏小。证据：`accepted/03-pretest-390.png`。
4. 实验一首屏（需改进）：粘性头部包含标题、身份、模式切换、四个操作按钮和横向步骤条，占首屏约 40%；步骤条需要横向滚动，后续步骤不可一眼发现。证据：`accepted/04-memory-top-390.png`。
5. 实验一操作区（严重）：固定助手在 390px 下占约 92×116px，覆盖正文、文本框边缘和底部操作按钮；“下一步”可能在滚动到位时仍被遮挡。证据：`accepted/05-memory-actions-390.png`。
6. 实验二宽表格（需改进）：表格移动端仍保持 440px 最小宽度，而可见容器约 217px，只能看到不到一半内容；虽然可以横向滚动，但阅读上下文割裂，助手同时覆盖正文。证据：`accepted/06-nback-table-390.png`。
7. 诊断入口（良好）：390px 下空状态和顶部操作正常回流；按钮约 43px 高，接近但略低于 44px 目标。证据：`accepted/07-diagnosis-390.png`。

## 修改计划

### P0：消除遮挡

- 修改 `assets/memory-partner.css` 的手机端规则：将助手收敛为 48–56px 的圆形启动按钮，隐藏常驻名称；为页面底部加入与浮层高度匹配的安全留白。
- 助手菜单打开时使用底部抽屉或接近全宽面板，并限制在安全区内；关闭后不得覆盖“上一步 / 下一步”、文本输入和主要提交按钮。
- 在 360、390px 下分别验证实验一至实验四的页尾操作区，确保固定控件与可交互元素没有矩形相交。

### P1：压缩实验页粘性头部

- 在 `memory.html`、`nback.html`、`interference.html`、`strategies.html` 的 `max-width: 640px` 规则中，将身份信息和低频操作折叠进“更多”菜单；首层只保留返回、当前实验标题和当前步骤。
- 手机端滚动后把头部压缩为约 56–72px，或让标题/操作区随页面滚走，仅保留紧凑步骤指示。
- 将所有顶部按钮与主题切换项的最小高度统一为 44px；同步调整 `assets/experiment-theme.css` 中当前 28px / 34px 的共享规则。

### P1：重做手机端步骤导航

- 不再在手机端展示 8 个 132px 横向卡片。改为“步骤 1/8 + 当前步骤名 + 上一步/下一步”，或 8 个紧凑圆点配当前步骤标题。
- 若保留横向滚动，进入页面和切换步骤时自动把当前项滚入可见区域，并提供明显的更多步骤提示；隐藏粗重的常驻横向滚动条。
- 四个实验页面使用同一移动端组件与样式，避免分别维护。

### P2：改善宽表格与长内容

- 在 `nback.html` 的移动端规则中取消 `.memory-table { min-width: 440px; }`。优先把每行转为“特点 / 说明”的堆叠卡片；若保留表格，至少让首列更窄、正文换行，并增加“左右滑动查看”提示。
- 检查四个实验中的表格、图表、量表和图片容器，确保 320–390px 下无需依赖隐藏内容或双向滚动完成阅读。

### P2：统一触控目标与移动端间距

- `login.html` 的显示密码按钮、游客入口，`pretest.html` 的顶部按钮，以及首页顶部操作统一达到至少 44×44px。
- 为 iPhone 安全区补齐顶部和底部 `env(safe-area-inset-*)` 间距；测试软键盘弹出时输入框和提交按钮仍可见。

## 验收标准

- 360×800、390×844、430×932 三个视口均无正文或主要按钮被固定元素遮挡。
- 实验页首屏至少保留 60% 高度给当前任务内容；滚动后粘性区域不超过 96px。
- 所有主要触控目标不小于 44×44px。
- 当前步骤无需横向探索即可识别；表格内容无需在不足半屏宽的窗口中阅读。
- 开启 200% 页面缩放后无关键内容丢失；键盘和读屏顺序需另做实际设备验证。

## 证据限制

本轮基于桌面浏览器的移动视口和截图进行排版审计，可确认响应式回流、遮挡和可见触控尺寸风险；不能据此宣称完整 WCAG 合规。真实 iOS/Android 的软键盘、安全区、触摸拖动、屏幕阅读器与性能仍需实机验证。
