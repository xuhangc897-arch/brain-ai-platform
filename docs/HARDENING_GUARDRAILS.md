# 平台工程加固长期注意事项

本文件是持续维护的工程护栏。后续每次修改都应检查并补充本文件，避免再次出现多版本逻辑并存、临时绕过长期保留和数据结构无版本演进等问题。

## 一、不可突破的原则

1. 学生实验业务逻辑和工程重构必须分开提交。
2. 未建立备份和回滚方案前，不修改或迁移历史实验数据。
3. 前端登录态不能作为服务端授权依据。
4. 后端不能信任客户端提交的学生身份字段。
5. 不在页面、日志或仓库中保存密码、密钥和 token。
6. 临时开关必须包含负责人、建立日期、删除条件和最迟删除日期。
7. 数据兼容不能通过读取时静默删除旧记录实现。
8. 新旧页面不得继续写入相同但结构不兼容的存储 key。
9. 一次修改只处理一个明确问题，避免跨模块顺手重构。
10. 每次修改必须更新本文件和 `HARDENING_CHANGELOG.md`。

## 二、当前工作区保护

## 三、每次修改前检查

- 明确本次允许修改的文件。
- 确认是否接触学生实验步骤、计时、评分或材料。
- 确认是否改变登录、身份或权限。
- 确认是否改变 localStorage key 或数据字段。
- 确认是否改变云函数输入输出。
- 确认是否需要真实 CloudBase 环境验证。
- 保存修改前的测试结果。

如果可能影响学生实验流程，应停止实施并先说明影响范围。

## 四、每次修改后检查

- 运行 `npm run check:baseline`。
- 查看 `git diff --check`。
- 确认最终 diff 只包含任务范围内文件。
- 按修改范围执行针对性测试。
- 记录测试成功、失败和未能验证的项目。
- 更新 `HARDENING_CHANGELOG.md`。
- 如发现新的长期风险，更新本文件。

## 五、数据结构变更护栏

任何数据结构变更都必须同时包含：

- 明确的 `schemaVersion`
- 新旧字段映射
- 可重复执行的迁移
- dry-run 模式
- 迁移前备份
- 数量和归属校验
- 失败报告
- 回滚方式

禁止在普通 `loadState()` 中执行不可逆的数据删除。

## 六、权限变更护栏

任何新增接口必须回答：

- 哪些角色可以调用？
- 服务端如何取得调用者 UID？
- 调用者可以访问哪些学生、班级或小组？
- 是否存在匿名路径或 HTTP fallback？
- 是否需要限速和审计日志？

权限测试必须包含未登录、学生越权、教师跨班级和伪造学生 ID。

## 七、新实验接入护栏

在实验注册表建立前，新增实验应暂停。注册表完成后，新实验至少必须提供：

- 唯一模块 ID
- schema 和版本号
- 状态初始化
- 提交数据构造
- 报告适配器
- 教师后台摘要
- 数据迁移策略
- 自动测试样本

不得通过复制现有完整 HTML 页面作为最终实现。

在该任务完成前：

- 记录每次测试实际使用的 Node.js 版本。
- 不因为本地高版本测试通过就假设云函数运行时兼容。
- 不在其他功能修改中顺带升级 Node.js。
- 运行时升级必须独立验证全部云函数和部署流程。

## 十、日志与调试响应

- 禁止记录密码、token、签名、Authorization、完整登录请求或完整用户对象。
- 数据库查询失败只记录必要错误码和请求追踪 ID，不记录查询结果或学生身份。
- 服务端调试字段不得因为前端排错方便而长期返回生产客户端。
- 增加日志前必须说明字段用途、保留周期和是否包含学生数据。
- 调试日志只能通过受控环境开关启用，生产环境默认关闭。
- 修改接口响应时必须先搜索全部调用方，确认未使用字段后再删除。

### 教师端与 CloudBase 特别约束

- 不得输出 CloudBase 完整 `loginState`、`currentUser` 或原始认证错误对象。
- 不得在教师导入页输出学生数组，即使密码字段已经遮盖；学号、姓名、班级和小组仍属于学生数据。
- 云函数调用诊断只记录错误码、目标函数和必要的布尔能力状态，不记录原始响应。
- 权限调用失败时不得新增匿名 HTTP 回退；现有回退必须在正式教师认证落地后单独移除并回归测试。
- 前端“已登录”只能控制界面展示，不能替代云函数服务端角色校验。

### 实验记录日志约束

- 查询日志只记录筛选字段名称，不记录学号、姓名、班级、小组或筛选值。
- 保存失败或跳过日志只记录模块、记录类型、数量、错误码及缺失字段状态。
- 不得记录完整实验载荷、`clientRecordId`、报告内容或 AI 对话正文。
- 需要关联单次请求时，应使用服务端生成且不包含业务字段的追踪 ID。

### 云函数错误响应约束

- 不得把 SDK 原始异常、异常堆栈或枚举后的异常对象直接返回浏览器。
- 业务失败响应只提供稳定错误码和面向用户的必要说明。
- 删除响应字段前必须检索所有调用方，并分别测试成功、跳过和失败路径。
- 详细内部错误只允许进入受控服务端日志，且仍需遵守敏感信息最小化规则。

### 学生端上传日志约束

- 共享上传器不得打印完整请求、完整响应、记录 ID 数组或原始异常对象。
- 成功日志最多记录模块、记录类型、写入数量和跳过数量。
- 失败日志最多记录 HTTP 状态、稳定错误码和不包含学生数据的异常类型。
- 页面不得再次打印共享上传器返回的完整结果；如需展示状态，应显式选择必要字段。

### 前端错误详情约束

- 浏览器控制台不得直接接收原始异常对象，只记录上下文、异常类型和稳定错误码。
- 面向教师的错误详情不得渲染 SDK 原始响应、完整异常、堆栈、登录态或当前用户对象。
- 页面可以展示完成操作所需的用户提示，但不得以“调试详情”为由扩大敏感信息范围。
- 权限识别等内部判断可以读取异常对象，但读取结果不得直接进入控制台、DOM 或接口响应。

### AI 助手日志约束

- 不得记录学生 ID、问题正文、回答正文、完整对话记录或包含身份的页面路径。
- 不得记录完整 AI 接口地址；地址可能包含环境标识、路由信息或临时查询参数。
- AI 后端错误日志只记录 HTTP 状态和稳定错误码，不记录完整响应对象。
- AI 请求诊断最多记录非身份化实验阶段和是否存在问题，不记录请求体。
- 对话记录上传日志只记录来源模块和条数，不记录上传载荷或学生身份。

### 语音助手日志约束

- 不得记录转写正文、音频数据、WebSocket 地址、签名参数或 ASR 原始事件。
- 麦克风、录音和识别异常日志只记录异常类型或稳定错误码。
- 面向用户的权限或连接提示与控制台诊断必须分离，不得直接复用原始异常对象。
- 修改语音日志时不得改变录音停止、资源释放、按钮恢复或转写回调顺序。

### AI 代理错误响应约束

- 不得把模型供应商的错误响应正文、异常消息、请求标识或内部路由信息返回浏览器。
- 上游失败只返回稳定错误提示；必要时可以包含 HTTP 状态，但不得包含响应正文。
- 服务端不得记录学生问题、完整上下文、模型回答或 Authorization 请求头。
- 成功与失败测试必须使用含测试秘密字段的模拟上游响应，验证秘密不会进入客户端响应。

### 本地静态服务器约束

- 文件路径边界必须使用 `path.relative()` 或等价文件系统语义判断，不得使用字符串前缀判断。
- URL 构造、百分号解码和路径规范化失败必须转为受控 4xx 响应，不得抛出到服务器事件循环。
- 路径测试必须覆盖正常文件、首页映射、父目录、同名前缀相邻目录、反斜杠编码和畸形百分号编码。
- 本地服务不得因为开发便利放宽到仓库根目录之外。

## 十一、安全止血阶段验收基线

后续任何修改都必须继续满足：

- 浏览器和服务端日志不包含密码、密钥、token、签名、完整 WebSocket 地址、学生身份、完整实验记录、AI 对话正文或原始异常对象。
- 面向前端的失败响应不包含 CloudBase SDK、数据库、模型供应商或 HTTP 网关原始错误正文。
- 页面不得打印共享上传器的完整返回对象；诊断字段必须显式选择。
- ASR、AI、登录、导入和实验上传的成功响应字段若需调整，必须先检查全部调用方并执行成功与失败路径测试。
- 修改已有实验页面时，应确认上传调用仍存在；仅删除日志不能顺带修改实验步骤、计时、评分、材料和报告。

当前明确不属于“已解决”的项目：

- 教师后台临时免登录。
- 匿名 HTTP fallback 和敏感云函数的服务端授权。
- 客户端可伪造学生身份及实验数据归属。
- 明文密码和可推导默认密码。
- CloudBase 权限规则、真实环境回归和运行时版本统一。

这些项目必须在后续核心认证与授权阶段单独设计、测试和回滚，不能以本阶段日志止血完成为由视为平台整体安全达标。

## 十二、统一契约护栏

- 浏览器配置、学生会话和实验上传契约以 `assets/platform-core.js` 为唯一运行时入口。
- 详细字段定义和加载顺序以 `docs/PLATFORM_CONTRACTS.md` 为准。
- 不得在页面中重新硬编码 CloudBase HTTP 地址、AI 地址、`studentSession` 或公共实验存储 key。
- `studentSession` key 和 v1 的 `studentId`、`name`、`class`、`group` 字段不得在无迁移方案时重命名或删除。
- `role` 只表示契约角色，不得被服务端当作已认证角色。
- 历史无 `schemaVersion` 数据按 v1 读取，不得在普通页面加载时自动批量回填。
- 新写入实验记录必须在上传信封、数据库文档和 `data` 中使用当前 `schemaVersion`。
- `clientRecordId` 算法变更属于数据去重变更，必须单独提供新旧映射和重复记录验证。
- 页面加载 `auth.js`、上传器、AI 助手或报告脚本前，必须先加载 `assets/platform-core.js`。
- 每次修改统一契约后必须运行 `npm run check:contracts` 和 `npm run check:baseline`。

## 十三、数据库 v2 与可靠上传护栏

- `experimentRecords` v2 字段定义、兼容字段和部署顺序以 `docs/DATABASE_MODEL_V2.md` 为准。
- 历史无版本/v1 文档不得因 v2 上线而批量删除、覆盖或回填。
- 新云函数必须同时接受 v1 和 v2 上传，直到完成有统计依据的旧客户端淘汰。
- v2 文档必须保留教师后台仍在使用的顶层 v1 兼容字段和 `data`。
- 确定性文档 ID 必须仅由完整 `clientRecordId` 的 SHA-256 产生，不得包含明文学号、姓名或实验正文。
- 不得把“先查后写”当作唯一幂等保证；并发写入必须收敛到同一文档 ID。
- outbox 必须在网络请求前落盘，成功或服务端确认重复后才能移除。
- outbox 必须按学生分区；当前学生不得上传、删除或覆盖其他学生的待上传记录。
- 游客数据不得进入云端 outbox。
- outbox 必须有数量上限和保留期限，不得无限保存学生实验数据。
- 网络、限流、服务端临时失败及滚动部署版本不匹配必须保留重试；明确无效数据不得无限重试。
- 批量写入必须返回逐条状态，单条失败不得阻止其他有效记录写入。
- 部署必须先升级兼容 v1/v2 的云函数，再部署发送 v2 的静态资源。
- 回滚必须先回滚前端，再回滚云函数。

## 十四、实验注册表与公共桥接护栏

- 实验 ID、通用显示名称、页面路由、报告元数据和模块 localStorage key 以 `assets/experiment-registry.js` 为唯一浏览器运行时来源。
- 页面不得重新建立模块名称、报告路由或实验状态 key 对照表。
- `assets/experiment-registry.js` 必须先于 `assets/platform-core.js` 加载；实验页的 `assets/experiment-bridge.js` 必须在上传器之后加载。
- 注册表模块 ID 与保存云函数允许模块集合必须完全一致，修改任一端时必须同步修改并运行契约检查。
- 公共桥接只允许封装完整状态提交和报告收尾，不得接管实验步骤、计时、随机化、评分、状态保存或特有过程记录。
- `submission` 的字段、调用顺序和 `clientRecordId` 格式不得因抽离而改变。
- 增加实验时不得复制现有完整状态提交拼装；应接入公共桥接，并为实验特有行为保留独立代码。
- 注册表新增条目必须检查 ID、路由和 storage key 唯一性；变更已有 storage key 必须先设计数据迁移和回滚。
- 教师后台的通用模块筛选和名称读取注册表；实验特有统计与导出必须显式实现，不得用不透明的动态分支替代。
- 每次修改注册表或桥接模块必须运行 `scripts/check-experiment-registry.js`、完整契约检查和基线检查。

## 十五、实验页面逐页迁移护栏

- 页面状态生命周期以 `assets/experiment-page-runtime.js` 为公共入口，具体边界以 `docs/EXPERIMENT_PAGE_MIGRATION.md` 为准。
- 公共运行时只负责状态 key、读取、页面回调、身份补齐、保存时间和落盘，不得理解或改写实验字段。
- 各页面的 `mergeState()` 和历史迁移必须保留在页面内；不得为了减少行数把不同实验的数据迁移混入公共运行时。
- 步骤校验、解锁、计时、随机化、评分、实验材料和事件顺序不得在状态生命周期迁移中修改。
- 保存顺序必须保持“页面同步回调 → 登录身份补齐 → `savedAt` → localStorage 写入”。
- 页面上下文合并后仍由登录身份覆盖同名身份字段；变更此顺序属于身份行为变更。
- N-back 的整体失败回退与其他页面的损坏 key 清理行为暂时保留，不得静默统一。
- storage key 或状态 schema 变更不属于页面迁移，必须另行设计迁移、备份和回滚。
- 每迁移一个页面都必须验证历史状态、损坏状态、刷新恢复、步骤导航和报告生成。
- 每次修改页面运行时必须执行 `scripts/check-experiment-page-migration.js`、完整契约检查和项目基线。

## 十六、教师后台、报告与 AI 整合护栏

- 三者共享的模块解析、路径识别、记录 payload/fullState 读取和构建器分发以 `assets/experiment-integration.js` 为入口。
- 详细边界与兼容规则以 `docs/EXPERIMENT_INTEGRATION.md` 为准。
- 报告页、AI 助手和教师后台不得重新建立模块名称或页面路径对照表。
- 整合层不得读取、记录、转换或返回 AI 问题与回答正文。
- AI 有效来源模块和 `clientRecordId` 格式不得因整合而改变；无效来源只能回退当前已注册页面。
- 报告活动回退规则变更属于用户可见行为变更，必须单独测试所有合法与非法 activityType。
- 教师导出构建函数保留模块特有实现；公共分发器不得把不同模块数据强行转换成统一字段。
- 教师查询参数、表格列、Excel sheet 名称或字段变更不属于本阶段，必须单独评审。
- 未知历史模块的导出回退不得静默改变或删除记录。
- 每次修改整合层必须执行 `scripts/check-experiment-integration.js`、完整契约检查、报告浏览器检查和教师后台浏览器检查。

## 十七、构建、部署、监控与遗留清理护栏

- 后续任何修改开始前必须完整阅读根目录 `修改须知.md`。
- 静态站点只能通过 `scripts/build-site.js` 生成的 `dist/` 发布，不得发布整个仓库。
- 发布包不得包含 `api/`、`cloudfunctions/`、`docs/`、`scripts/`、数据库备份、开发服务器、配置文件或历史副本。
- `dist/health.json` 和 `dist/deploy-manifest.json` 必须由构建生成，不得手工编辑。
- GitHub Pages 使用 Actions artifact 部署，Pages Source 必须为 GitHub Actions。
- Pull Request 只能构建和校验，只有 `main` 或明确手动触发可以部署。
- 部署任务必须具有最小的 `pages: write`、`id-token: write` 和 `contents: read` 权限。
- 部署后和定时监控只能执行只读 GET，不得登录、提交表单、读取学生数据、调用 AI 或写 CloudBase。
- 监控失败时必须保留首次失败证据，先区分构建、Pages、缓存和网络问题，再决定重试或回滚。
- 回滚使用 `git revert` 和完整重新部署，不重写 `main` 历史，不手工覆盖单个公共脚本。
- 遗留清理前必须证明无引用、无部署依赖且可恢复；数据库备份和高风险临时开关不得作为普通文件清理。
- 每次构建或部署修改必须运行 `npm run verify`、`npm run build`、`npm run check:dist`，并更新运维文档。

## 十八、学生端响应式布局护栏

- 实验页手机端布局变更必须限定在明确的窄屏媒体查询内；不得通过修改桌面基础规则顺带改变桌面端布局。
- 四个实验页共享的手机端头部和步骤导航样式以 `assets/experiment-theme.css` 为入口，页面通过 `experiment-page` 类显式加入；资格审查等其他页面不得被实验页专属规则误伤。
- 手机端固定虚拟人必须保留足够的页面底部安全留白，页尾主操作按钮不得与启动器相交；菜单展开后仍须受视口和安全区约束。
- 窄屏步骤导航必须同时满足全部步骤可发现、当前步骤可识别和触控目标不小于 44×44px；视觉隐藏的步骤标题仍须保留在无障碍名称中。
- 宽表格在手机端必须换行或转换为可读布局，不得把不足半屏宽的横向滚动窗口作为唯一阅读方式。
- 响应式修改至少验证 390px 手机视口和 1440px 桌面视口，并记录头部定位、固定浮层尺寸、横向溢出和主要触控目标；桌面端粘性头部、完整步骤文字和原组件尺寸应保持不变。
