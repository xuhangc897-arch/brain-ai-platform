# 后续实验页面分页改造须知

本须知适用于实验二、实验三、实验四的分页改造。整体分页逻辑、交互方式和单屏标准应与实验一保持一致，但必须保留各实验原有文案、字段、数据记录、上传、登录和权限逻辑。

## 一、分页原则

将每个实验步骤从“长页面滚动阅读”改为“多页面单屏阅读”。

每个子页面必须满足：

- 桌面端内容完整显示在当前屏幕内。
- 不依赖上下滚动阅读或操作。
- 按材料顺序、任务顺序和内容主题分页。
- 不拆散必须同时对照的信息。
- 不通过缩小到难以阅读的字号强行塞入单屏。
- 优先压缩空白、调整双栏布局或继续拆页。
- 手机端保持响应式，但单屏无滚动主要按桌面端验收。

建议使用与实验一一致的轻量结构：

```js
const pages = [
  {
    title: "",
    className: "",
    content: () => ``
  }
];
```

为每个步骤设置非持久化页码：

```js
const stepPageIndexes = {
  question: 0,
  hypothesis: 0,
  plan: 0,
  evidence: 0
};
```

页码仅用于当前页面会话：

- 不写入 localStorage。
- 刷新后从该步骤第 1 页开始。
- 原有实验填写内容仍按原逻辑恢复。

## 二、分页导航规则

每个子页面顶部显示当前进度，例如：

```text
提出问题 1/4
制定计划 2/5
搜集证据 1/3
```

页面底部使用与实验一相同的固定导航：

```text
上一页                    下一页
```

具体规则：

- 实验第一个子页面隐藏“上一页”。
- 步骤内部点击“下一页”只切换子页面。
- 步骤最后一页点击“下一页”调用原有步骤跳转逻辑。
- 原有字段验证仍在进入下一教学步骤时执行。
- 点击“上一页”可以返回当前步骤的前一子页面。
- 当前步骤第一页继续点击“上一页”时，可返回上一教学步骤的最后一页。
- 页面切换使用约 150ms 的淡出、淡入动画。
- 支持 `prefers-reduced-motion`，用户减少动态效果时取消动画。
- 子页面数量可根据实验记录动态增加，例如搜集证据结果每 3 轮增加一页。

## 三、内容拆分要求

按照以下顺序判断是否需要分页：

1. 不同材料分别分页。
2. 材料阅读与填写任务分别分页。
3. 操作说明与正式实验分别分页。
4. 参数设置与步骤排序分别分页。
5. 数据记录、数据分析与结论填写分别分页。
6. 内容仍超出单屏时继续按主题拆分。

以下内容应尽量放在同一页：

- 需要直接比较的两种实验方法。
- 同一问题的个人思考与小组共识。
- 同一组简短参数。
- 同一轮测量的基本信息和结果。
- 相互依赖、必须同时查看的操作说明。

个人思考与小组共识在桌面端优先采用双栏布局，移动端再改为单栏。

## 四、“作出假设”页面规则

所有实验的“作出假设”步骤均不需要展示科学探究案例或研究问题案例。

该步骤只保留：

- 必要的简短假设提示。
- 个人研究假设输入。
- 小组研究假设输入。
- 原有字段名、保存行为和验证规则。

不要把“提出问题”步骤中的案例重复到“作出假设”。

## 五、图片展示规则

若材料图片尺寸较大，或直接显示会导致页面超出单屏，应改为按钮触发展示。

页面正文只保留：

```text
点击查看……
```

点击后打开悬浮图片框：

- 图片框居中显示。
- 使用遮罩层与正文区分。
- 图片按比例缩放，不裁切。
- 最大高度不超过当前视口。
- 提供清晰的关闭按钮。
- 点击遮罩空白处可关闭。
- 按 `Esc` 可关闭。
- 关闭后焦点回到触发按钮。
- 档案模式下悬浮框也必须使用档案主题样式。

不要因为图片过大而让整个教学页面产生纵向滚动。

## 六、“制定计划”与“搜集证据”参数统一

搜集证据页面如果出现了与制定计划相同的实验参数，应删除重复的可编辑下拉框或输入框。

例如：

- 实验材料类别。
- 测量方法。
- 呈现时间或间隔。
- 起始难度。
- 刺激类型。
- 实验条件。
- 任务顺序。
- 组别或条件分配。

处理原则：

- 参数只在“制定计划”中设置一次。
- “搜集证据”直接读取制定计划中的值。
- 搜集证据页面以只读文本、标签或摘要卡显示。
- 正式测量必须使用制定计划中的值。
- 不允许学生在搜集证据阶段再次自行切换。
- 不新增重复字段。
- 不改变原有数据记录字段和上传结构。
- 若必须修改参数，应提供“返回制定计划修改”按钮，而不是在搜集证据页面增加第二套控件。

## 七、“搜集证据”页面优化规则

搜集证据页面应区分三个状态。

### 1. 未开始测量

只显示：

- 参与者信息。
- 从制定计划同步的只读参数。
- 当前自动生成的测量序号。
- 简短操作提示。
- “开始测量”按钮。

删除没有实际意义的内容，例如：

- 空统计卡。
- 空日志表。
- 占位字符或装饰性实验区。
- 尚无数据时显示的复杂图表。
- 与制定计划重复的参数控件。

### 2. 正在测量

只显示完成任务需要的信息：

- 当前刺激。
- 当前序列长度或难度。
- 回答输入区。
- 提交按钮。
- 必要的作答规则。
- 必要的实时状态。

测量期间优先保持低干扰、专注式界面，不显示无关装饰和冗余历史数据。

### 3. 测量结束

测量结束后，应让学生清晰看到本轮完整数据，包括：

- 参与者编号。
- 测量序号。
- 实验方法。
- 实验材料或实验条件。
- 起始参数。
- 各阶段或各长度的全部试次。
- 每次作答的正确、错误状态。
- 本轮最终结果。
- 测量是否有效。
- 失败或无法精确测得时的明确说明。

结果必须按独立测量轮次分组，优先使用 `runId`，不要把不同尝试错误合并。

建议：

- 每个结果卡展示一轮测量。
- 每页最多展示 3 轮。
- 记录更多时通过步骤内“上一页 / 下一页”查看。
- 不使用长表格造成整页滚动。
- 失败轮可以保留展示，但是否计入平均值必须遵循该实验原有或明确修订后的计算规则。
- 追加测量使用自动编号，不恢复手动选择测量次数的下拉框。

## 八、档案模式全局检查

每完成一个实验，都必须检查该实验所有步骤在档案模式下是否存在科技模式的蓝色残留。

重点检查：

- 标题和页码。
- 按钮及悬停状态。
- 输入框焦点边框。
- 单选框、复选框和选中状态。
- 卡片边框与背景。
- 标签和状态标记。
- 进度条。
- 表格表头。
- 图表颜色。
- 图片悬浮框。
- 测量专注界面。
- 正确、错误与警告状态。
- SVG 图形的填充色和描边色。
- 阴影、渐变和半透明蓝色。
- `:hover`、`:focus`、`:active`、`:checked` 等交互状态。

检查时不能只搜索颜色名称，还应检查：

```css
#2563eb
#1d4ed8
#4f7cff
#dbeafe
#bfdbfe
#eff6ff
#eef6ff
rgb(...)
rgba(...)
linear-gradient(...)
box-shadow
```

处理要求：

- 优先使用已有主题变量。
- 新增组件必须同时支持科技模式和档案模式。
- 档案模式使用纸张、棕色、米色、墨色和档案绿色等现有配色。
- 不应为了去蓝而影响科技模式原有样式。
- 不修改其他实验，除非当前任务明确包含该实验。

## 九、修改范围约束

改造某个实验时：

- 只修改当前指定实验。
- 不主动抽象大型公共组件。
- 不修改其他实验的文案和流程。
- 不修改登录和权限逻辑。
- 不修改 CloudBase 上传逻辑。
- 不修改 localStorage 结构。
- 不随意更改实验记录字段。
- 不删除已有数据。
- 不重写与分页无关的代码。
- 原有验证规则原则上保持不变；若页面结构导致验证入口变化，只调整触发位置。
- 新增页码状态默认不持久化。

## 十、验收清单

每个实验完成后至少检查：

- 1366×768、1440×900、1920×1080 下默认页面无需纵向滚动。
- 所有子页面的按钮位置稳定且不遮挡内容。
- 第一页正确隐藏“上一页”。
- 中间页能够前后切换。
- 最后一页能够执行原步骤验证并进入下一教学环节。
- 刷新后页码回到第 1 页，但已填写字段仍能恢复。
- 作出假设页面没有案例。
- 大图片通过悬浮框查看。
- 搜集证据没有重复参数下拉框。
- 制定计划中的参数与实际测量参数完全一致。
- 未测量时没有空统计区和无意义占位内容。
- 测量结束后所有试次结果清晰可见。
- 多轮记录能够分页查看。
- 科技模式显示正常。
- 档案模式没有蓝色残留。
- 原有实验记录、导出和上传字段保持兼容。
- `npm run verify` 通过。
- `git diff --check` 通过。
- 最终差异只包含本次指定实验的相关修改。
