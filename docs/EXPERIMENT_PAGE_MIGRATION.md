# 实验页面逐页迁移说明

本文档定义阶段 5 对五个实验页面的迁移边界。迁移目标是统一页面状态生命周期，同时保留每个实验已有的数据结构、历史兼容逻辑和学生操作流程。

## 一、已迁移页面

迁移按以下顺序完成：

1. `poster.html`
2. `memory.html`
3. `interference.html`
4. `strategies.html`
5. `nback.html`

五个页面均通过 `assets/experiment-page-runtime.js` 创建与注册表模块绑定的页面运行时。

## 二、公共运行时职责

`window.BrainExperimentPageRuntime.create(moduleId)` 负责：

- 从实验注册表取得该页面的状态 storage key。
- 从平台核心取得统一探究上下文 key。
- 读取并解析已有实验状态。
- 调用页面自己的 `mergeState()` 合并默认值与历史数据。
- 调用页面自己的上下文应用函数。
- 按原顺序用当前登录身份补齐状态。
- 保存前执行页面提供的同步回调。
- 写入 `savedAt` 并保存完整状态。

公共运行时不解释或修改实验状态字段。

## 三、保留在页面内的逻辑

以下内容继续由各实验页面独立负责：

- 默认状态与历史字段迁移。
- 步骤数组、当前步骤和解锁范围。
- 每一步的完成校验。
- 计时、随机化、刺激材料和作答处理。
- 实验结果、评分与统计。
- 调查问卷、知识测验和报告内容。
- 实验特有过程记录与上传。
- DOM 渲染和事件绑定。

这些内容不能在没有页面级行为测试的情况下继续抽入公共运行时。

## 四、错误兼容

原页面存在两种损坏数据处理方式，本阶段均保持：

- `memory`、`interference`、`strategies`、`poster`：损坏的实验状态或上下文会删除对应 key，并继续使用可恢复数据。
- `nback`：状态读取、合并或上下文读取任一步失败时，返回默认状态，不删除原 key。

这两种行为暂时不统一。若以后统一，必须作为数据恢复策略变更单独处理。

## 五、增加或迁移实验页面

1. 先在实验注册表建立模块。
2. 按规定顺序加载注册表、平台核心、认证、上传器、桥接和页面运行时。
3. 使用 `BrainExperimentPageRuntime.create(moduleId)` 取得状态 key 和上下文 key。
4. 将页面原 `mergeState()` 作为回调传入，不要搬入公共运行时。
5. 保存时把页面原保存前同步函数作为 `beforeSave` 传入。
6. 为正常历史数据、损坏数据、身份覆盖和保存顺序增加测试。
7. 完成人工步骤导航、实验操作、刷新恢复和报告生成回归。

## 六、回滚

回滚时应同时恢复：

- `assets/experiment-page-runtime.js`
- 五个实验页面的脚本引用、运行时绑定、`loadState()` 和 `saveState()`
- 对应测试和文档

本阶段没有修改 storage key 或状态 schema，因此回滚不需要迁移或删除 localStorage 数据。
